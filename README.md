## Задание 1. Git как доказательство авторства

### Ход работы
1. Инициализирован локальный репозиторий в папке `lab14` (команда `git init`).
2. Создан файл `text.txt`, в который вносились изменения (создавались разные версии).
3. Каждое изменение фиксировалось с помощью коммитов (`git commit`).
4. История изменений просмотрена командой `git log`.

### Как коммиты фиксируют авторство и дату
Каждый коммит в Git содержит:
- Уникальный хеш (SHA-1), который зависит от содержимого файлов, автора, даты и предыдущего коммита.
- Имя и email автора.
- Точную дату и время создания коммита.
Поскольку хеш каждого нового коммита основан на предыдущем, изменить старые записи незаметно невозможно — это сломает всю цепочку. Поэтому история коммитов служит надежным доказательством авторства и хронологии.

## Задание 2. Запрет на копирование

### Ход работы
Создана веб-страница `index.html`, на которой реализованы методы защиты текста от копирования.

**Примененные методы:**
1. **CSS:** свойство `user-select: none` (и его вендорные префиксы) запрещает выделение текста мышью.
2. **JavaScript:** блокировка контекстного меню (событие `contextmenu`).
3. **JavaScript:** блокировка горячих клавиш `Ctrl+C`, `Ctrl+X`, `Ctrl+A`, `Ctrl+U` (событие `keydown`).
4. **JavaScript:** блокировка события `copy`.

### Какие методы наиболее эффективны
Наиболее эффективным является **CSS-метод (`user-select: none`)**, так как он блокирует само выделение на уровне отрисовки браузера и не требует выполнения скриптов. JavaScript-методы (блокировка ПКМ и клавиш) менее надежны: их легко обойти, отключив JavaScript в браузере, или просмотреть исходный код страницы. Стоит отметить, что абсолютной защиты контента на стороне клиента не существует — любые методы являются лишь барьером для обычных пользователей.
